# scripts — operational scripts that run on the machine

Thirteen scripts, in two groups.

**Most of them run on the Fly machine**, where `DATABASE_URL`, `ANTHROPIC_API_KEY` and the generated
Prisma client already exist:

```bash
fly ssh console -a contentclaude -C "node /app/scripts/<name>.mjs"
```

Anything you upload to `/app` is wiped by the next deploy, so upload, run, read the output, and do not
expect it to still be there tomorrow:

```bash
MSYS_NO_PATHCONV=1 fly ssh sftp put ./scripts/<name>.mjs /app/<name>.mjs -a contentclaude
```

Browser-driving proof harnesses are **not** here — they are in `tools/proof/`, they run from a laptop,
and several of them write to a live shop. The split is deliberate: these two things had been in one pile
and it was not possible to tell at a glance which was which.

## The names say what they do

A script name that does not say whether it writes is a trap at 2am. These say it.

| Script | Default | What it does |
|---|---|---|
| `backfill-faq-metafields--dry-run-default.mjs` | **dry run** | Repairs FAQ metafields that were recorded as published but are missing live. Idempotent, resumable. `--apply` to write. |
| `fix-legacy-alttext-rows--dry-run-default.mjs` | **dry run** | Marks pre-fix alt-text rows failed — they were stored as published but never reached Shopify. `--apply` to write. |
| `test-seed-usage--writes-test-store-only.mjs` | **writes** | Inserts synthetic usage rows to exhaust a dev shop's quota, so the upgrade prompts can be photographed without spending 25 real generations. **Refuses any shop it does not recognise as a test store.** `SEED_ACTION=restore` removes them. |
| `webhook-probe--writes-fake-shop-only.mjs` | **writes** | Sends real HMAC-signed webhook deliveries to production and prints the status and time for each. This is what found the 88.5% failure rate. **Refuses any domain but the fake probe shop**, because app/uninstalled deletes everything for the shop in the header. Removes its own GDPR audit rows. |
| `generate-schema-columns.mjs` | read-only | Regenerates the expected-column list the schema-drift guard compares against. Run it after ANY change to `prisma/schema.prisma`; a test fails if the committed list is stale. `--check` exits 1 instead of writing. Touches no database. |
| `ttv-report.mjs` | read-only | Time-to-first-value, review-ask outcomes, upgrade funnel. No writes. |
| `diag-shop.cjs` | read-only | One shop's install, plan and session state. |
| `shop-install-diag.cjs` | read-only | Install and reinstall history. |
| `store-products-diag.cjs` | read-only | Product and generated-content counts for a shop. |
| `shop-settings-diag.mjs` | read-only | One shop's STORED settings straight from the database — the toggle flags, `storeName`, `language`, and character counts rather than the merchant's own copy. Use it when you must compare what is stored against what the app renders; those are two different things. Also reachable without a Fly token via the **Shop settings diagnostic** workflow. |
| `logs.mjs` | read-only | **INFRA2 — the durable log.** `fly logs` keeps ~100 lines; this queries the 30-day `LogEvent` table (WARN-and-above plus tagged events). `--since 2h` · `--around 2026-09-10T03:45 --window 10m` · `--event autopilot_withheld` · `--shop x.myshopify.com` · `--level warn`. Never writes. |
| `paid-plans-diag.mjs` | read-only | **B8 — "grandfather nobody", verified instead of believed.** Counts Plan rows by name and status and reports how many hold an ACTIVE paid subscription. The whole locked pricing change (allowances x4-7.5, bulk moved a tier) is harmless if that number is zero and is a change with a person on the other end of it if it is not. Prints **no shop domain and no charge id** — a subscription GID identifies a merchant's billing record and this output goes into a CI log. Reachable without a Fly token via the **Paid plans check** workflow. |
| `archived-generations-diag.mjs` | read-only | **P5.1 — has this app ever spent a merchant's credits on a product they ARCHIVED?** Under credit weighting that stopped being cosmetic: a generation is a real charge at 2.00¢, and `app.optimize.jsx` walked the catalogue with **no `query` argument at all**, so bulk optimize enqueued work against archived products. Phase 4's A1 scoped the three READ paths on the Products page and left the WRITE path — the one that costs money. Per shop, intersects the archived product ids in Shopify today with the distinct products we hold content for. Prints **no product id, no title and no shop domain** (handles only); an uninstalled or unrefreshable shop is reported as `reachable: false` rather than folded into the total as a zero. Reachable without a Fly token via the **Archived generations check** workflow. |
| `byok-roundtrip--writes-test-shop-only.mjs` | **writes one dev-shop row, then removes it** | **P6.0 — proves the installed BYOK encryption secret WORKS, not merely that it is present.** A secret corrupted in transit gives a feature that appears to work (card renders, save succeeds) and cannot decrypt anything afterwards. Encrypts a SYNTHETIC value — not an Anthropic key, authenticates nothing — stores it, reads it back through the real `resolveKeyFor`, compares in constant time, and deletes the row. Refuses any shop that is not a dev store, and refuses to overwrite a row that already holds a key. Prints only booleans: never a value, a prefix or a length. Reachable via the **BYOK round-trip check** workflow. |
| `support-close--writes-one-row.mjs` | **writes ONE row's status** | **P7 C2 — mark a support request answered, by reference.** First use: closing CC's own end-to-end test submission so the owner's first real queue does not carry it. Prints the reference and the resulting status only — never a message body, never an address. Refuses a reference it cannot find. Reachable via the **Support — close a request** workflow. |
| `catalogue-watch--writes-snapshots.mjs` | **writes ProductWatch rows** | **P2.3 — run the catalogue watch now, for every installed shop, and print what it found.** The same function the 02:00 Sydney job calls, so a green run here is evidence about the job. Counts and kinds only: no shop domain, no handle, no product title. Reachable via the **Catalogue watch** workflow. |
| `first-run-reset--writes-one-shop.mjs` | **writes ONE column on ONE Shop row** | **P2.7 proof tooling — put one of our own dev stores back on the first-run screen** by nulling `Shop.firstDraftSeenAt`. Refuses any shop that does not match the dev-store name pattern (`navaal-ttv-*`, `navaal-qa-*`, `contentpilot-dev*`), so a merchant store can never be reset from here. Nothing in Shopify. The next Home load on that store writes up to three drafts through the normal quick-start path. Reachable via the **First-run reset (one dev store)** workflow, which takes the shop as an input. |
| `plan-rebase--writes-plan-rows.mjs` | **writes Plan.monthlyCredits** | **A1 (Phase 8) — raise every active Plan row that is below the locked table to the locked number for its plan name.** Favourable only, by construction (`app/utils/planRebase.js`); nothing is ever lowered and rows above the table are left alone. Prints per-plan counts before and after. Reachable via the **Plan re-base** workflow. `getOrCreatePlan` also does this on read, so the script is the one-shot for the rows nobody has loaded yet. |
| `support-and-gdpr-diag.mjs` | read-only | **P6.2 — is anybody waiting on a reply, and do the GDPR webhooks DO anything?** The listing promises one business day; a promise with nothing looking at the queue is one nobody can keep. Reports open questions, how many are past a day, and — the one that matters most — how many were **stored but never emailed**, which is invisible unless something asks. Also counts `GDPRRequest` rows per type, because a handler that returns 200 and writes nothing looks identical to a working one from Shopify's side, and checks the audit row holds no customer email. Prints shop handles and subjects, **never an email address and never a message body**. Runs weekday mornings and on demand via the **Support and GDPR check** workflow. |
| `xss-exposure-diag.mjs` | read-only | **P0 / A5 — how much stored FAQ content contains markup that WOULD have rendered on a merchant storefront.** `faq_visible.liquid` interpolated AI-generated FAQ text with no `| escape` and Liquid does not auto-escape; `toPlainText` sanitisation only entered `faqToJsonLd` in the same commit (`7942c30`), while metafield writing began `894e34f` on 2 Jul — a **69-day window** of unsanitised content rendered unescaped, because the escaping reached storefronts only on 2026-09-14. Reads every `contentclaude.faq_schema` metafield per shop and counts angle brackets, entity forms, `</script>` and tag-like strings. **Stricter privacy than every other script here: no shop domain, no handle — an index and a class only — and never any metafield content, because reproducing a payload into a CI log is publishing it.** Reachable via the **XSS exposure check** workflow. |
| `score-cache-diag.mjs` | read-only (deletes one cache key) | **P5.2 — how long a merchant waits for the store score to catch up with what they published.** `startscan:<shop>` was the only cache key in the app that was written and NEVER cleared — every other one has an invalidator — so a merchant who published and went back to Home saw the score from before they pressed the button, for up to ten minutes, with nothing saying so. Reads the key's real TTL, calls the exact function the three publish paths call, and confirms it is gone. Touches no store and no merchant row. Reachable without a Fly token via the **Score cache check** workflow. |
| `tokens-observe--spends-api-credit.mjs` | **spends API credit + 1 generation credit** | **C2 — proves `UsageRecord.tokensUsed` is non-zero in PRODUCTION.** The write path was proved by test in `5bd4fb8`; a write path proved only by its own test is false green #4 in `07-VERIFICATION.md`, and if it is broken in production then every cost figure in `08-ECONOMICS.md` §2 — and the locked pricing built on $0.0115/credit — becomes unverifiable. Runs ONE real generation through the real gate (withGenerationCredit → AsyncLocalStorage → ai.server.js → recordTokensUsed) and then reads the row straight back from the database. Touches **nothing in Shopify** — it never opens an admin client. **Never point it at a live commercial catalogue.** Reachable via the **Observe tokensUsed** workflow. |
| `measure-generation-cost--spends-api-credit.mjs` | **spends API credit** | **P0.6 — the measurement every `ASSUMED` figure in `08-ECONOMICS.md` was waiting for.** Makes real Anthropic calls through the real `app/utils/ai.server.js` functions — not a re-implementation, because a re-implementation would measure a prompt I wrote today rather than the prompt merchants are billed for — and reports mean input/output tokens and USD per content type. Touches **no** Shopify store and **no** database: the product is a fixture in the file and it never opens a Shopify client. `--samples N` · `--image-url <cdn.shopify.com URL>` (without it `altText` reports **NOT MEASURED** rather than a guess) · `--types a,b` · `--json`. Needs the key, so run it on the machine or through the **Measure generation cost** workflow. |

Anything with `--apply`: **run it without the flag first and read the output.** Both backfills print
exactly what they would change.

## The two that run on a laptop, not on the machine

These need no `DATABASE_URL` and no Fly token. They are here rather than in `tools/proof/` because they
drive no browser and touch no shop — they read this repository and the public production endpoints.

| Script | Default | What it does |
|---|---|---|
| `check-api-versions.mjs` | read-only | **P0.3 — the guard against being delisted for an aged-out API version.** Fails when any pin is within 90 days of sunset (sunset = release + 12 months), when an extension whose type *takes* an `api_version` declares none or one below **2025-10** (the React → Polaris floor), or when a type that takes *no* `api_version` declares one. An extension type it has not met must pin, so a new type fails loudly rather than being waved through, and it fails on finding no pins at all — a check that passes by finding nothing is decoration. Runs in CI before `npm ci`; locally it is `npm run check:api-versions`. Reads files only. |
| `screen-numbers.mjs` | read-only | Reads the numbers a merchant actually sees off Home, Products and the SEO Audit, in ONE browser session so they are comparable — A2's defect was two numbers a minute apart being 42 points different, so reading them an hour apart would prove nothing. Also reports form VALUES, which `innerText` cannot see. Needs the saved Shopify session; sends a real Chrome UA, because Playwright's default gets 410 Gone from Shopify's bot filter and the resulting error page reads exactly like "the feature is missing". |
| `wait-for-deploy.sh` | read-only | Proves a push actually reached production (L19). Waits for the CI run **for one specific commit sha**, then polls `/api/build-info` until the live sha equals it, then requires deep health with the worker running and the schema check green. Scoped to a sha on purpose: the ad-hoc version of this asked "has the most recent run finished?", matched a *previous* completed run and reported a deploy that had never happened. `scripts/wait-for-deploy.sh [sha]`, defaulting to HEAD. |
